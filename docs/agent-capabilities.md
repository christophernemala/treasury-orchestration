# Treasury Atom Agent Capabilities & Workflows\n\n## Executive Summary\n\nTreasury Atom embeds four specialized AI agents designed for corporate treasurers:\n\n1. **Excel Report Generator** — Produce auditable cash position, reconciliation, and exception reports\n2. **Cash Flow Forecaster** — Generate T+7, T+30, T+90 liquidity scenarios\n3. **Reconciliation Proposal Engine** — Auto-match bank transactions to GL with confidence scoring\n4. **Exception Detector** — Identify duplicates, stale items, threshold violations, anomalies\n\nAll agents are **deterministic, auditable, and explainable** — no hallucinations, every decision traced.\n\n---\n\n## 1. Excel Report Generator Agent\n\n### What It Does\n\nAutomates creation of production-ready Excel workbooks with:\n- Daily/weekly/monthly cash position summaries\n- Bank statement reconciliation status (% matched)\n- GL matching analysis with drill-down detail\n- Control total verification (9 mandatory controls)\n- Exception reports with root cause analysis\n\n### Real-World Example\n\n**User Action**: Click `[Generate Monthly Report]` for September 2026\n\n**Agent Steps**:\n1. Query all bank accounts for legal entity → 2 accounts, total 2.591M AED\n2. Fetch normalized GL ledger → 2.474M matched, 117.950M unmatched\n3. Validate control totals (TCTRL-001 through TCTRL-009)\n4. Generate 5 Excel sheets: Summary, Accounts, Transactions, Controls, Audit Trail\n5. Embed checksum in workbook metadata\n6. Create audit log entry (action: `REPORT_GENERATED`, actor: `user-001`, timestamp: `2026-09-15T14:32:00Z`)\n7. Return download link + embedded signature\n\n**Output Filename**: `Treasury_Atom_Report_2026-09-15_14-32-00.xlsx`\n\n### Supported Report Types\n\n| Report Type | Contents | Use Case |\n|---|---|---|\n| **Cash Position** | Daily balances, available/restricted split, facility headroom | Board reporting, external audit |\n| **Reconciliation** | Bank → GL matching, confidence scores, exceptions | Month-end close, CFO review |\n| **Exceptions** | Duplicates, stale items, threshold violations | Compliance audit, risk reporting |\n| **Audit Trail** | All maker-checker actions, signatures, timestamps | SOX compliance, forensic review |\n| **Control Totals** | 9 mandatory controls reconciliation | Internal audit, release gate |\n\n### API Endpoint\n\n```typescript\nPOST /api/v1/agents/report/generate\n\nRequest:\n{\n  \"reportType\": \"reconciliation\",\n  \"legalEntityIds\": [\"entity-001\", \"entity-002\"],\n  \"dateRange\": {\n    \"from\": \"2026-09-01\",\n    \"to\": \"2026-09-30\"\n  },\n  \"format\": \"xlsx\",\n  \"requiresApproval\": true  // Checker must approve before distribution\n}\n\nResponse (202 Accepted):\n{\n  \"taskId\": \"task-report-001\",\n  \"status\": \"PROCESSING\",\n  \"estimatedCompletionSeconds\": 15,\n  \"downloadUrl\": null  // Populated when ready\n}\n```\n\n### Validation & Security\n\n- ✅ All numbers cross-validated against GL source\n- ✅ Excel formulas use `=SUMIF()` for auditability\n- ✅ Workbook encrypted with user's API key\n- ✅ Distribution audit logged (who opened, when, from where)\n- ✅ Requires Checker approval for external distribution\n\n---\n\n## 2. Cash Flow Forecasting Agent\n\n### What It Does\n\nGenerates forward-looking liquidity forecasts in 3 scenarios:\n- **Base Case** (70% probability) — Historical patterns + known payments\n- **Optimistic** (15%) — Early collections + delayed payments\n- **Pessimistic** (15%) — Late collections + accelerated payments\n\n### Real-World Example\n\n**User Action**: Open \"Liquidity Dashboard\" → click `[30-Day Forecast]`\n\n**Agent Steps**:\n1. Load approved payment orders for next 30 days → 45 payments totaling 15.2M AED\n2. Load historical inflow patterns (last 90 days) → average 2.1M AED/day\n3. Query facility agreements → 2.5M AED available headroom\n4. Load covenant thresholds (min daily balance: 500k AED)\n5. Generate daily forecast:\n   - Day 1: Opening 2.1M + inflows 1.5M - outflows 500k = 3.1M (✅ above threshold)\n   - Day 2: 3.1M + 800k - 1M = 2.9M (✅)\n   - ...\n   - Day 18: 1.2M + 300k - 2M = -500k (⚠️ BELOW THRESHOLD → trigger facility draw)\n6. Insert facility draw on Day 18 automatically\n7. Generate final forecast with visualization\n\n**Output**: Interactive dashboard + downloadable CSV\n\n```\nDate       | Opening  | Inflows | Outflows | FX    | Closing   | Facility | Status\n2026-09-15 | 2,100k   | 0       | 0        | 0     | 2,100k    | 0        | TODAY\n2026-09-16 | 2,100k   | 1,500k  | (500k)   | (5k)  | 3,095k    | 0        | ✅ OK\n...\n2026-10-03 | 800k     | 300k    | (2,000k) | 10k   | (890k)    | 1,000k   | ⚠️ FACILITY DRAW\n```\n\n### API Endpoint\n\n```typescript\nPOST /api/v1/agents/forecast/generate\n\nRequest:\n{\n  \"scenarioType\": \"base\" | \"optimistic\" | \"pessimistic\",\n  \"forecastHorizon\": \"T+7\" | \"T+30\" | \"T+90\",\n  \"legalEntityIds\": [\"entity-001\"],\n  \"includeCovenants\": true,\n  \"includeFacilities\": true,\n  \"assumptions\": {\n    \"inflowGrowth\": 1.05,  // 5% above historical\n    \"outflowVariance\": -0.10  // 10% below expected\n  }\n}\n\nResponse:\n{\n  \"forecast\": {\n    \"scenario\": \"base\",\n    \"horizon\": \"T+30\",\n    \"minimumBalance\": 1205000,\n    \"minimumBalanceDate\": \"2026-10-03\",\n    \"covenantBreachRisk\": false,\n    \"facilityDrawRequired\": true,\n    \"facilityDrawDate\": \"2026-10-03\",\n    \"facilityDrawAmount\": 1000000,\n    \"dailyForecasts\": [ ... ]\n  }\n}\n```\n\n### Variance Analysis\n\nAgent automatically computes sensitivity:\n\n```json\n{\n  \"sensitivityAnalysis\": {\n    \"inflowVariance\": {\n      \"-20%\": { \"minimumBalance\": 850000, \"breachRisk\": true },\n      \"0%\": { \"minimumBalance\": 1205000, \"breachRisk\": false },\n      \"+20%\": { \"minimumBalance\": 1560000, \"breachRisk\": false }\n    },\n    \"outflowVariance\": {\n      \"-10%\": { \"minimumBalance\": 1100000, \"breachRisk\": false },\n      \"0%\": { \"minimumBalance\": 1205000, \"breachRisk\": false },\n      \"+10%\": { \"minimumBalance\": 1310000, \"breachRisk\": false }\n    }\n  }\n}\n```\n\n---\n\n## 3. Reconciliation Proposal Engine\n\n### What It Does\n\nAutomatically matches bank transactions to GL journal entries using multi-factor scoring:\n\n```\nConfidence Scoring:\n- Exact amount match: +100 points\n- Amount within ±0.01 AED: +95 points\n- Amount within ±1%: +80 points\n- Date exact match: +0 points (already weighted in amount)\n- Date within ±1 day: +20 points\n- Date within ±3 days: +10 points\n- Reference substring match (invoice#): +40 points\n- Counterparty name match: +30 points\n\nMinimum threshold for proposal: 60 points\nMinimum threshold for auto-approval: 100 points\n```\n\n### Real-World Example\n\n**User Action**: Import bank statement CSV → agent runs automatically\n\n**Bank Transaction**: \n```\nDate: 2026-09-15, Amount: 100,000 AED, Reference: \"INV-2026-001\", Counterparty: \"Acme Corp\"\n```\n\n**Agent Finds 3 Candidate GL Entries**:\n\n| Journal ID | Amount | Date | Description | Scoring | Confidence |\n|---|---|---|---|---|---|\n| JE-001 | 100,000 | 2026-09-15 | \"Customer Invoice INV-2026-001\" | 100 (exact amount) + 0 (exact date) + 40 (ref match) = **140** | **100% → AUTO-APPROVE** |\n| JE-002 | 100,000 | 2026-09-16 | \"Payment Acme Corp\" | 100 + 10 (±1d) + 30 (counterparty) = **140** | **100% → AUTO-APPROVE** |\n| JE-003 | 99,850 | 2026-09-15 | \"Customer Acme Invoice\" | 95 (±0.15% variance) + 0 + 30 = **125** | **88% → PROPOSE** |\n\n**Agent Output**:\n```json\n{\n  \"proposals\": [\n    {\n      \"bankTxn\": \"btxn-001\",\n      \"proposedJournal\": \"JE-001\",\n      \"confidenceScore\": 100,\n      \"recommendation\": \"AUTO_APPROVE\",\n      \"requiresReview\": false,\n      \"scoringBreakdown\": {\n        \"amountExact\": 100,\n        \"dateExact\": 0,\n        \"referenceMatch\": 40\n      }\n    }\n  ],\n  \"unmatched\": [\n    {\n      \"bankTxn\": \"btxn-002\",\n      \"reason\": \"NO_CANDIDATES\",\n      \"suggestions\": []\n    }\n  ]\n}\n```\n\n### Maker-Checker Workflow\n\n1. **Maker** (Treasurer) runs reconciliation\n2. **Agent** proposes matches with confidence scores\n3. **Checker** (Controller) reviews:\n   - Auto-approved matches (100 confidence) — shown in green, can spot-check\n   - Proposed matches (60-99 confidence) — shown in yellow, must approve individually\n   - Unmatched — shown in red, requires manual investigation\n4. **Checker** approves or rejects; action logged\n5. **Approved matches** locked in audit trail\n\n---\n\n## 4. Exception & Anomaly Detector\n\n### What It Does\n\nContinuously monitors for:\n\n| Exception Type | Detection Logic | Severity | Action |\n|---|---|---|---|\n| **Duplicate Transactions** | Same amount + reference + date (±24h) | HIGH | Hold for review |\n| **Stale Unmatched Items** | Bank txn unmatched > 30 days | MEDIUM | Escalate to treasury |\n| **Threshold Violation** | Payment amount > approval limit | HIGH | Block, require L2 approval |\n| **Missing GL Entry** | Bank debit with no corresponding GL | HIGH | Flag as exception |\n| **FX Anomaly** | Conversion spread > historical avg + 2σ | MEDIUM | Review for market impact |\n| **Weekend/Holiday Posting** | Clearing on non-business day | LOW | Flag for investigation |\n\n### Real-World Example\n\n**Scenario**: Duplicate payment detected\n\n```json\n{\n  \"exception\": {\n    \"type\": \"DUPLICATE_TRANSACTION\",\n    \"severity\": \"HIGH\",\n    \"detectedDate\": \"2026-09-15T10:45:00Z\",\n    \"affectedTransactions\": [\"btxn-001\", \"btxn-002\"],\n    \"amount\": 500000.00,\n    \"reference\": \"PAYMENT-2026-001\",\n    \"dateRange\": {\n      \"first\": \"2026-09-15T08:30:00Z\",\n      \"second\": \"2026-09-15T09:15:00Z\",\n      \"deltaSeconds\": 2700  // 45 minutes apart\n    },\n    \"recommendation\": \"HOLD_BOTH_PENDING_INVESTIGATION\",\n    \"actions\": [\n      \"Block matching until resolved\",\n      \"Alert Treasury Lead\",\n      \"Generate exception report\"\n    ],\n    \"escalationPath\": \"Treasury Lead → Finance Controller → CFO\"\n  }\n}\n```\n\n---\n\n## Integration
