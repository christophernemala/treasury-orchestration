# AGENTS.md — AI Agent Configuration for Treasury Atom\n\n## 1. Identity & Mission\n\nTreasury Atom is an enterprise, high-assurance corporate treasury management platform built with React 19 / Vite + Node.js / Express 5.\n\n- **Base Currency**: `AED` (United Arab Emirates Dirham)\n- **Precision**: Exact decimal arithmetic (`Decimal.js` or fixed 2-decimal string math). IEEE 754 floating point numbers are strictly forbidden for balances, journals, and settlements.\n- **Security Invariants**: JWT lifetimes capped at 15 minutes, single-use 6-digit dev OTPs, membership-based tenant and legal entity scoping, fail-closed production boundaries, dynamic SSE stream reconciliation.\n\n---\n\n## 2. Quick Start & Developer Commands\n\n```powershell\n# Install dependencies\nnpm ci\n\n# Build both client and server\nnpm run build\n\n# Run local dev server (Express on :4320, Vite client on :5173)\nnpm run dev\n\n# Run Vitest test suite (56 automated tests)\nnpm run test\n\n# Run quality checks (build + test)\nnpm run check\n```\n\n---\n\n## 3. Architectural Rules & Invariants\n\n### 4.1 Persistence & Database\n- Uses Node.js standard library `node:sqlite` (`DatabaseSync`) located in `.runtime/treasury.db`\n- In-memory database `:memory:` used for fast, isolated test runs\n- PostgreSQL with Row-Level Security (RLS) for production (Supabase)\n- All monetary amounts stored as integers (2-decimal AED precision)\n\n### 4.2 Separation of Duties (Maker-Checker)\n- High-value transactions (>100k AED) and invoices require dual control\n- User who created request (`makerId`) **cannot** approve it (`checkerId ≠ makerId`)\n- Dual Checker required for transactions >500k AED\n- All approvals cryptographically signed and immutable\n\n### 4.3 Tenant & Legal Entity Scoping\n- Every read and write validates active user's legal entity assignments (`legalEntityIds`)\n- Cross-entity linkage strictly denied with `403 ENTITY_SCOPE_DENIED`\n- RLS policies enforce at database level\n- SSE subscriptions scoped to user's entities only\n\n### 4.4 Fail-Closed Security\n- In production (`NODE_ENV=production`), missing identity or persistence adapters fail closed with `503`\n- Development routes (`/api/seed`, `/api/v1/dev/reset`) never exposed in production\n- All unauthenticated or out-of-scope requests return `401` or `403` immediately\n- No graceful degradation; security always takes precedence\n\n### 4.5 Deterministic Intelligence\n- Agents provide explainability, matching proposals, and anomaly alerts\n- Agents **never** bypass required human approvals\n- Agents **never** write unverified transactions to ledgers\n- All agent recommendations include confidence scores and decision logic\n- Agent executions logged for audit trail\n\n---\n\n## 5. AI Agents: Purpose, Rules, and Workflows\n\n### Agent 1: Excel Report Generator\n\n**Purpose**: Generate auditable Excel workbooks with cash position, reconciliation, control totals, and exception analysis.\n\n**Inputs**:\n- Legal entity IDs (user's assigned entities only)\n- Date range\n- Report type (cash-position, reconciliation, exceptions, audit-trail)\n\n**Outputs**:\n- Multi-sheet Excel workbook with:\n  - Executive summary (cash available, pending approvals, reconciliation %)\n  - Bank accounts detail (balances, last update)\n  - Transactions detail (matched, proposed, unmatched)\n  - Control totals (9 mandatory controls: TCTRL-001 through TCTRL-009)\n  - Audit trail (immutable maker-checker chain)\n\n**Security Rules**:\n- ✅ Only entities user is scoped to\n- ✅ All amounts validated against GL source\n- ✅ Formulas use `=SUMIF()` for auditability\n- ✅ Checksum embedded in metadata\n- ✅ Requires Checker approval before external distribution\n- ✅ Distribution audit logged (who, when, from where)\n\n**API Endpoint**:\n```\nPOST /api/v1/agents/report/generate\n```\n\n---\n\n### Agent 2: Cash Flow Forecasting\n\n**Purpose**: Generate forward-looking liquidity scenarios (T+7, T+30, T+90) with covenant monitoring and facility optimization.\n\n**Inputs**:\n- Scenario type (base / optimistic / pessimistic)\n- Forecast horizon\n- Legal entity IDs\n- Covenant & facility inclusion flags\n\n**Outputs**:\n- Daily cash flow forecast with:\n  - Opening balance, inflows, outflows, FX impact, closing balance\n  - Minimum balance date and amount\n  - Covenant compliance status\n  - Facility draw requirements (date, amount)\n  - Sensitivity analysis (what-if scenarios)\n\n**Security Rules**:\n- ✅ Only entities user is scoped to\n- ✅ Forecasts include only approved payment orders\n- ✅ Historical inflow patterns anonymized (no customer names)\n- ✅ Facility utilization transparent\n- ✅ Covenant thresholds enforced\n- ✅ Variance assumptions explainable\n\n**API Endpoint**:\n```\nPOST /api/v1/agents/forecast/generate\n```\n\n---\n\n### Agent 3: Reconciliation Proposal Engine\n\n**Purpose**: Automatically propose GL matches for bank transactions using multi-factor confidence scoring.\n\n**Inputs**:\n- Bank statement ID\n- Proposal threshold (default: 60)\n- Auto-approval threshold (default: 100)\n\n**Outputs**:\n- Proposed matches with:\n  - Confidence score (0-100)\n  - Scoring breakdown (amount, date, reference, counterparty)\n  - Recommendation (AUTO_APPROVE, PROPOSE_TO_CHECKER, HOLD_FOR_REVIEW)\n  - Unmatched transactions with reasoning\n\n**Confidence Scoring**:\n```\nExact amount match:        +100 points\nAmount within ±0.01 AED:   +95 points\nAmount within ±1%:         +80 points\nDate exact match:          +0 points (already weighted in amount)\nDate within ±1 day:        +20 points\nDate within ±3 days:       +10 points\nReference substring match: +40 points\nCounterparty name match:   +30 points\n\nMinimum to propose:        60 points\nMinimum to auto-approve:   100 points\n```\n\n**Security Rules**:\n- ✅ Only entities user is scoped to\n- ✅ Auto-approval only for 100-score matches (no exceptions)\n- ✅ All other proposals require Checker review\n- ✅ Maker cannot approve own proposals\n- ✅ Reversals only by Dual Checker\n- ✅ All matches immutable once approved\n\n**API Endpoint**:\n```\nPOST /api/v1/agents/reconciliation/propose\n```\n\n---\n\n### Agent 4: Exception & Anomaly Detector\n\n**Purpose**: Identify duplicates, stale items, threshold exceptions, missing GL entries, and FX anomalies.\n\n**Inputs**:\n- Monitoring scope (statement, entity, date range)\n- Exception severity thresholds\n\n**Outputs**:\n- Categorized exceptions:\n  - **Duplicates**: Same amount, reference, date (within 24h) → HOLD_FOR_REVIEW\n  - **Stale Unmatched**: Unmatched >30 days → ESCALATE_TO_TREASURY\n  - **Threshold Exceptions**: Amount >approval limit → BLOCK, require L2 approval\n  - **Missing GL Entries**: Bank debit with no GL → FLAG_FOR_INVESTIGATION\n  - **FX Anomalies**: Conversion spread >historical avg + 2σ → REVIEW\n\n**Security Rules**:\n- ✅ Only entities user is scoped to\n- ✅ High-severity exceptions escalate to Finance Controller\n- ✅ Never auto-resolve exceptions (always require human review)\n- ✅ Resolution audit logged with justification\n- ✅ Unresolved exceptions retained indefinitely\n\n**API Endpoint**:\n```\nGET /api/v1/agents/exceptions?entityId=...&daysUnresolved=30\n```\n\n---\n\n## 6. Boundaries & What Agents Cannot Do\n\n❌ **Agents cannot**:\n- Bypass dual-control approvals\n- Write to GL without verified source\n- Auto-reverse completed transactions\n- Approve own proposals (Maker-Checker violated)\n- Access entities outside user's scope\n- Execute payments (only propose)\n- Modify master data (accounts, thresholds, facilities)\n- Disable audit logging\n- Override failed reconciliations without Checker\n\n✅ **What humans must always do**:\n- Approve high-value proposals\n- Resolve exceptions\n- Authorize GL reversals\n- Adjust facility limits\n- Override agent recommendations\n- Review control total mismatches\n- Sign off on close procedures\n"
